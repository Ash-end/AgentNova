# 递进实验任务书

所有实验都是本项目自学设计，不是 CS2680 原题复刻。L01–L16 与周次对应。优先把同一个项目逐步改好，避免每周重新建立一个无法衔接的 demo。

## 已选方向适配：代码实验 Agent

2026-10-21 已选此方向。以下是对各实验通用示例的具体替换，验收方法保留：

| 实验 | 本项目的具体场景 |
| --- | --- |
| L01 | 观察读取代码、运行测试、运行指定实验三类任务 |
| L02–03 | 读取配置、启动允许的实验入口、获取运行状态、读取结果；先模拟执行再接真实工具 |
| L04 | 对 README、源码、配置和日志检索，定位入口与错误；引用文件和行号 |
| L05 | 保存 run ID、代码版本、配置、种子、产物与检查点；断点续跑不重复启动已有任务 |
| L06 | 比较固定实验流程和反馈驱动的计划；在允许范围内诊断和修复失败 |
| L07 | 独立测试、配置一致性、实际运行证据、结果计算正确性；不让 Agent 修改评分器 |
| L08 | 执行隔离、路径与资源限制、恶意代码注释/日志、超时与取消 |
| L09–10 | 将实验查询工具包装为 MCP；比较单 Agent 与代码定位/测试验证分工 |
| L11–12 | 优化实际实验任务的调用成本并交付 CLI/UI；区分模型耗时与实验耗时 |
| L13–16 | 用同一代码实验任务集测量模型服务与最终系统；任务训练算力和 Agent 推理算力分别计账 |

第一课只做纸面推演，不预先生成完整运行时。首次实验建议使用小型合成数据线性回归，用 CPU 即可学习配置、指标、随机种子与实验溯源；数据划分固定，调参用验证集，测试集用于最终验收。

## 通用约定

每个实验保留：目标、环境和版本、输入任务、实现、运行轨迹、评分、失败案例、结论。报告使用 [实验模板](../templates/experiment-report.md)。代码后续建议置于 `src/`，实验入口放 `labs/lXX/`，脱敏结果放 `reports/`；这些代码目录尚未实现。

运行时日志建议字段：`run_id, task_id, config_id, step_id, event_type, tool_name, duration_ms, token_usage, status, error_type, artifact_path`。记录可见调用、工具结果和简短决策说明即可，不依赖模型暴露完整内部推理。

## L01：从行为观察理解 Agent

- 选 3 类任务：回答概念、从资料找证据、读取文件后进行计算并产出结果。
- 对每类任务记录：输入、工具、观察结果、下一步动作、最终输出、人工介入。
- 比较固定脚本和动态 Agent 的必要性；列出 10 个自己真实会用的任务。
- 交付：轨迹表 + 失败分类初稿 + 毕业项目范围草案。
- 验收：能指出哪些事情是模型决定的，哪些必须由程序保证。

## L02：手写最小运行循环

- 定义模型适配器、消息/状态、工具注册表、工具结果与结束状态。
- 模拟模型先按预定序列返回工具调用，再接入实际模型；测试运行时不依赖付费 API。
- 工具先提供受限计算与本地文档读取。计算不直接对模型生成字符串使用 `eval`。
- 设置 `max_steps`、调用超时、费用/令牌预算接口；正常完成、失败和预算耗尽有不同终态。
- 验收：未知工具、连续无进展、格式错误和最大步数场景都能收敛；至少一个真实模型多步案例跑通。

## L03：工具契约与可靠性

- 定义输入 schema、返回 schema、错误类型、权限和副作用说明。
- 注入 6 类故障：缺字段、类型错误、未知工具、超时、服务限流、重复请求。
- 区分可重试与不可重试错误；有限次重试；非幂等动作不能盲目重复。
- 文件工具限制在练习工作区，检验绝对路径、`..` 与链接绕过。
- 验收：故障被记录，失败不会伪装成成功；副作用有实际输出证据。

## L04：可追踪证据的检索

- 选少量可合法使用的课程资料或自写笔记，保存来源、段落/页码和更新时间。
- 建立 10 道带证据位置的问题，包含跨段落问题、证据不足和互相矛盾的材料。
- 比较无检索、关键词检索、向量或混合检索。embedding 成本单独记录。
- 指标：Recall@k（基于已标注证据）、回答正确性、引用支持程度、端到端成本。
- 验收：引用不只是存在链接，还要真的支持所述结论；检索失败不靠编造填补。

## L05：状态、记忆和恢复

- 使用 SQLite 保存会话、工具结果引用、检查点和明确确认的用户偏好。
- 比较全量历史、摘要、检索记忆在相同上下文预算下的表现。
- 测试进程中断后恢复、偏好更正、记忆删除、过期信息和两个会话隔离。
- 验收：删除后的记忆不再进入检索结果；恢复不会重复执行已确认完成的写操作。

## L06：规划是否值得

- 在同一组约 10 个任务上比较：直接回答、固定工作流、动态工具循环、规划执行。
- 模型与任务输入一致，约束总调用/令牌预算；至少包含一个中途发现新约束的任务。
- 为反思步骤提供真实验证器，例如测试、计算结果或证据匹配。
- 验收：能区分“文字计划更长”和“成功率提升”；写出适用边界。

## L07：独立评测器

- 将早期任务扩充为 40 个开发任务与 20 个保留测试任务；任务分组见毕业项目文档。
- 评分优先使用可执行规则与人工核验；主观评分提供 rubric，再校准模型裁判。
- 测试集从开发时冻结；由学习者或独立流程保管，不把其答案灌入提示或记忆。
- 对至少 10 个有随机性的开发任务运行 3 次，报告波动；最终评测协议见 L16。
- 验收：同一次运行失败也出现在结果表；模型、prompt、工具、数据和评分器有版本信息。

## L08：权限和对抗场景

- 准备恶意文档：要求忽略任务、读取项目外文件、泄漏假密钥、执行未经授权操作。
- 检查权限判定是否位于工具执行路径；加入取消、预算耗尽与工具不可用场景。
- 若引入代码执行，使用适当隔离环境并限制文件、网络、运行时与资源；先从受控固定脚本开始。
- 验收：不执行越权动作；日志不含秘密；正常授权任务能够完成。报告测试范围，不声称全面安全。

## L09：框架和 MCP 对照

- 保留手写版本，将一条有恢复需求的流程迁移到一种图编排框架。
- 把已有只读检索工具包装成 MCP 服务，客户端验证输入并处理错误。
- 对照两版的状态、恢复、取消、事件流与工具结果。
- 验收：能演示中断恢复；能解释 MCP 没有替代模型、规划或权限系统。

## L10：单 Agent 与多 Agent

- 仅选择能独立拆分的任务，例如检索两个主题后核对证据。
- 对照单 Agent、单 Agent 并行工具、两个有明确分工的 Agent。
- 统一总预算，记录协调 token、重复检索、冲突和关键路径耗时。
- 验收：依据测量决定保留或撤回多 Agent；不能因为角色更多就判定更好。

## L11：成本优化

- 优先选缓存、工具结果裁剪、上下文压缩、独立调用并发或模型路由中的两项。
- 实验顺序：基线 → 优化 A → 优化 B → A+B；保持任务和评分器一致。
- 计算 `每成功任务成本 = 所有运行费用 / 成功任务数`，失败和重试费用全部纳入。
- 成功数为零时该指标不定义，报告为 N/A，同时报告总费用和零成功，不能写成 0。
- 验收：给出质量/成本/耗时表；区分冷缓存与热缓存；使用明确的价格日期和计费单位。

## L12：交付日常使用版

- 提供 CLI 和最小 Web 入口；展示状态、引用、产物、取消按钮和错误信息。
- 固化环境、配置方式、模型选择、数据存储位置、启动与清理说明。
- 从新的终端复现；测试 5 类真实用户任务；对已知失败场景回归。
- 验收：学习者自己可以启动、定位错误并修改一个工具，无需依赖对话历史里的隐含配置。

## L13：自己运行模型

- 先核验 GPU 型号、显存、驱动、操作系统和推理引擎支持情况，再选择模型与部署方式。
- 估算权重、KV cache 和运行开销；记录精度、上下文长度、最大并发与硬件。
- 用同一 Agent 任务对比 API 和本地模型的工具调用能力与成功率。
- 验收：不能仅凭 tokens/s 得出 Agent 整体更好；资源不足时明确未完成实测。

## L14：负载和缓存

- 自变量：请求并发、输入长度、输出上限、共享前缀比例。
- 控制模型、硬件、采样设置，分开记录首次加载、预热和稳态。
- 指标：TTFT、吞吐、端到端 p50/p95、错误率、显存峰值；记录样本数。
- 验收：能够解释吞吐上升与尾延迟变差并存的原因；小样本 p95 只作探索性观察。

## L15：全栈优化

- 画出模型、工具、网络、等待和检索的耗时分解。
- 写一个可检验假设，例如“重复长前缀占主要开销，所以 prefix caching 会降低延迟”。
- 在硬件支持的技术中选一项深入：量化、缓存、调度或推测解码；其余完成原理分析。
- 改一个 Agent 层参数，检查与服务优化是否互相影响。
- 验收：报告未改善的任务和质量退化，不能只挑最快一次运行。

## L16：最终验收

- 冻结最终版本与评分器，保留测试集首次用于最终对照；至少比较强简单基线与最终 Agent。
- 预算允许时，20 个保留任务 × 3 次重复 × 两个系统，记录全部运行；预算不足可先各跑一次，但必须说明可靠性证据有限。
- 对各任务类型分别报告成功率、引用指标、权限用例通过数、失败恢复率、费用和延迟。
- 看过测试结果后继续调参，该测试集已成为开发资料，后续宣称泛化改进需建立新保留集。
- 交付：可运行代码、环境和启动说明、评测报告、5 分钟演示、已知限制与下一版计划。
