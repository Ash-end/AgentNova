## 实现范围

新增 experiment_agent/ollama_loop.py，以 Ollama 原生消息格式保存完整 assistant/tool 历史，自动执行整批工具请求并继续请求模型。新增 labs/l11_real_agent_loop.py，准备真实 HTTP 请求、打印过程、保存各轮快照。原有 mock 循环及文件工具保持原实现。

一步表示一次模型请求；达到上限即停止，不自动重试网络请求。无工具请求且有完整非空文本才记为 completed；该状态只代表协议结束，不代表独立评估证明任务正确。


实际耗时 0.522 秒，模型请求 1 次、工具读取 1 次且成功，随后因没有最终回答的决策机会返回 failed / max_steps_exceeded，退出码 1，符合预期。报告独立保存为 reports/l11_real_agent_loop_steps1.json。

这是最小真实工具循环；其他文件异常的统一处理、任务结果的独立验证、更多工具和更完善的预算仍在后续课程范围内。

## 学习者独立运行与反馈

学习者贴出 l11 成功输出：completed、模型决策 2 次、工具执行 1 次、内容正确，总耗时 0.858 秒；两次模型请求分别约 0.534 秒和 0.322 秒，加载均约 0.003 秒且各命中 354 个输入缓存 token。本次运行条件与 AI 首次冷加载不同，不将耗时差异归因于代码优化。

全部 29 项测试由学习者独立运行通过，耗时 0.055 秒。

学习者正确解释 continue 结束当前一轮并进入下一轮，但随后将 content 中“我先读取文件”与实际执行读取联系起来，需要澄清程序执行主体：Python 已在 continue 之前调用文件工具；删除 continue 后会执行原消息的 content 判断，非空时提前返回 completed，模型没有收到工具观察。若原 content 为空，则返回 empty_model_response，也不会发起下一轮请求。复述与独立修改尚未验收。

后续学习者正确复述：messages.append 只把工具结果保存在消息列表，要等下一轮 chat(messages, tool_descriptions) 才真正发送给模型。这一处理解已确认；代码独立修改尚未验收。
