# 第 1 课：代码实验 Agent 如何工作

状态：教学材料已提供，等待学习者练习；尚未验收。预计本次 20–30 分钟，后续依据回答推进，不一次完成整周内容。

## 本课目标

能区分模型、工具、运行时和环境反馈，并用自己的话描述“根据运行结果决定下一步”的过程。

## 贯穿课程的任务

> 在一个小型线性回归项目中比较学习率 0.01 与 0.1。保持数据划分、初始化种子和训练步数一致，报告验证集 MSE 与耗时。如果执行失败，先诊断，最多进行有限次恢复尝试。

这是教学任务设定，代码尚未实现，下面的工具与日志都是示意，不是实际运行结果。先学这个小实验的系统机制，后续再换成深度学习项目。

## 四个组成部分

| 部分 | 职责 | 在这个任务中的例子 |
| --- | --- | --- |
| 模型 | 根据目标与已知信息提出动作或答案 | 发现配置字段未知，决定先读取配置 |
| 工具 | 提供具体可调用能力 | 读取文件、启动实验、查询状态、读取指标 |
| 运行时 | 管理循环、状态、验证、预算、停止和恢复 | 验证参数，再调用工具，把结果放回会话 |
| 环境 | 任务实际作用的代码、进程、文件与机器 | Python 训练进程、配置文件、指标和错误日志 |

模型生成 `run_experiment(...)` 的调用请求时，还没有执行训练。运行时实际调用工具之后，才会发生环境变化。工具返回值也需要校验，不能只因进程退出码为 0 就断定指标正确。

## 最小运行循环

```text
接收目标与约束
    ↓
模型依据当前状态提出动作
    ↓
运行时验证参数、权限和剩余预算
    ↓
工具作用于环境，返回实际观察
    ↓
记录状态与证据
    ↓
根据新信息继续、请求必要输入、失败退出或完成
```

一个简化表述是 `动作 = 策略(目标, 历史观察)`。在我们的实现里，模型承担一部分策略，程序负责约束与执行。不要假设模型能直接看到内存、文件或进程；未通过工具提供的状态通常不在它的可见信息里。

固定 workflow 的动作顺序主要由代码预先确定；动态 Agent 可以根据新观察选择不同工具和路径。两者可组合。对于已经明确的两个学习率对照，固定脚本可能就足够；遇到未知项目结构、缺失输入、运行故障时，才需要比较动态决策是否有实际价值。

## 示意轨迹

| 步骤 | 动作 | 观察 | 下一步依据 |
| --- | --- | --- | --- |
| 1 | 读取 README 和配置 | 找到实验入口、参数及指标输出约定 | 可以建立两份仅学习率不同的配置 |
| 2 | 启动第一组实验 | 返回 run ID 和运行中状态 | 之后查询状态，不能立刻报告实验成功 |
| 3 | 查询状态 | 非零退出状态，日志说明缺少输入文件 | 应先诊断输入问题，不能假定重试必然恢复 |
| 4 | 在允许范围内检查输入 | 根据实际观察确定能否恢复 | 可恢复则有限重试，否则清楚报告阻塞 |
| 5 | 两组均完成后读取结果 | 得到各自配置、run ID、指标与耗时 | 验证可比性和指标有效性后生成报告 |

失败的实验没有产生有效 MSE，就应记为“失败/无有效指标”，不能记为 MSE=0，也不能凭预期填数字。完成不要求某个学习率一定胜出；如果结论是两者差异不明显，也可以是正确结果。

## 第一轮练习：先在聊天里回答

```json
{
  "run_id": "demo-001",
  "status": "failed",
  "exit_code": 1,
  "stderr": "FileNotFoundError: data/train.csv",
  "metrics": null
}
```

1. 你会让 Agent 下一步做什么？说明需要补充哪一项信息。
2. 除了上面的字段，你认为还应保留哪两项信息，便于追踪和复现实验？
3. 什么时候应该停止尝试，并向用户报告失败？

不查资料也可以，用自己的工程直觉作答。导师根据回答讲解，不预先把学习者标记为掌握。
