## 起始诊断题

这些题用于确定解释深度，不要求第一天全会。

1. “请解释 ReAct”“从三份资料比较 ReAct 和规划执行”“运行两种策略并报告指标”，分别需要哪些能力？哪些任务用脚本就够？
2. 模型返回了一个工具名称和 JSON 参数，为什么不能直接执行？还缺哪些检查？
3. 模型说“文件已保存”，什么证据才能证明真的保存成功？
4. 一次 API 调用超时后重试，什么时候安全，什么时候会产生重复副作用？
5. 为什么模型变强了，整个 Agent 仍可能经常失败？
6. 怎样区分检索失败、理解失败、工具失败和运行时失败？
7. 多 Agent 比单 Agent 多解决一个任务，是否足以说明架构更好？还要控制哪些条件？
8. 如果模型权重能装进显存，为什么服务长上下文请求仍可能 OOM？这题不会可留到系统阶段。

## 本周验收

- 能画出模型、运行时、工具、环境反馈之间的关系。
- 有 3 条实际观察记录，至少 1 个失败分析；未观察到失败时可设计故障实验，但注明是主动注入。
- 有 10 个真实任务和成功标准，明确毕业项目的首个范围。
- Anaconda 解释器路径正确；普通 Python 工具能处理正常与非法输入。
- 能解释本周自己的脚本，独立修改一个输入约束。

本周不要求做漂亮 UI，不要求多 Agent，不要求 GPU 部署。第 2 周的核心是把现有工具接进自己写的模型调用循环。
